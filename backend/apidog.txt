Step 1 — Start the Server

  Run this in your terminal (keep it running), from backend/:

  uvicorn main:app --reload --port 8000

  Your base URL is: http://127.0.0.1:8000

  Note: this is the SAME apidog collection as
  ~/coding/laravel-api-mawrid/apidog.txt — every request below is byte-for-byte
  the same Method/URL/Body you'd send to the Laravel API. Only the base URL
  changes (Laravel used port 8000 too, so if you're switching between the two,
  just make sure only one server is running on that port at a time).

  This Python backend supports more provider prefixes than the Laravel one:
  groq/<model>, gemini/<model> (both APIs have), plus claude/<model>,
  openrouter/<model>, ollama/<model> (local, no key needed).

  Step 2 — What to Look For if Something Goes Wrong

  If you get an error, check the terminal running uvicorn (it prints the
  full Python traceback for anything not already caught).

  Common issues:
  - 422 with {"error":"validation_failed", ...} → wrong field name, missing
    required field, or invalid JSON body
  - 400 with "No API key for groq" → the matching *_API_KEY isn't set in .env
  - 502 with "Invalid API Key" → the key is set but wrong/expired — check
    the provider dashboard
  - 502 "model not found" / similar → the model name is wrong for that provider
  - Pipeline timeout → increase your client's timeout or try a smaller file

  Note: all errors under /api/mawrid/* come back shaped like Laravel's —
  {"error": "validation_failed"|"server_error", "message": "..."} — so any
  error-handling logic you already wrote against the Laravel API works
  unchanged here.

  ---
  Extra: the native Python API (not in the Laravel version)

  Everything above also exists under the original Python route names, with
  slightly different defaults/behavior (used by the React frontend):

  GET    /health
  GET    /api/schema
  POST   /api/schema/upload        (upload a custom schema, get a token back)
  POST   /api/two-stage/run        (same as pipeline/run, form-data, all 3 stages)
  POST   /api/saved
  GET    /api/saved
  GET    /api/saved/{id}/file
  DELETE /api/saved/{id}

  You generally don't need these if you're just testing feature parity with
  the Laravel collection — use the /api/mawrid/* routes above for that.
